OPlus primary command-mode optical UDFPS compatibility opt-in
============================================================

Build option: CONFIG_OPLUS_OFP_UIREADY_COMPAT=y
Default: undefined or 0 (retain the legacy OFP path).
Only the integer value 1 selects the compatibility path.

Use this opt-in only for a validated product whose primary command-mode
optical panel/HAL combination takes press from DIM/FINGERPRESS connector
bits and needs a fresh READY after each touch. No new device-tree property
is required. Existing fp_type and panel mode configuration remain inputs.

The reader checks the resolved LOCAL_HBM and
LOCAL_HBM_UNLOCKING_ACCELERATION bits and rejects secondary panels,
LCD/OLED capacitive, ultrasonic, video-AOD/FOD and 30 Hz video-AOD modes.
It latches the decision during OFP initialization, before callback
publication. Do not change it at runtime or fall back to the legacy worker
while an opted-in owner is stopping.

A product enables this from its BoardConfig.mk. The display Kbuild turns it
into the build define for every display object:

    TARGET_KERNEL_ADDITIONAL_FLAGS += CONFIG_OPLUS_OFP_UIREADY_COMPAT=y

The four kernel changes share this opt-in: property press, READY rearm,
owned delivery and TP_DOWN reevaluation. Products that do not select it
retain the legacy worker, notifier, timer and teardown paths. An enabled
binary is not a per-device runtime selector for multi-product distribution.

The same opt-in latches the press from the first compositor FOD bit until
touch up. Composition changes during enrollment drop those bits while the
finger is still down, and capture needs LHBM for the whole press. A touch
alone never starts a press, and power off clears the latch.

The opt-in does not select a sensor or alter fp_type, panel brightness,
HBM timing, calibration or biometric algorithm thresholds. Existing
IRQ/display object lifetime and session teardown serialization remain
caller responsibilities. No new claim of multi-panel lifetime safety is
made by this compatibility series.

DSI lifecycle hooks and fatal OFP-init error propagation require both the
SM8750 API marker and OPLUS_OFP_UIREADY_COMPAT=1. Other builds retain the
legacy unchecked init call. OFP init keeps optional parsing best effort;
owned-session construction failure is cleaned up before returning an
error. The panel error path may repeat partial cleanup after that unbind,
which is a no-op. Pass the define consistently to all display objects.
